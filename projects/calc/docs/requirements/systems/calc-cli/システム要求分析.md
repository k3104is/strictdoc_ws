# calc CLI システム要求分析

## 1. システムコンテキスト

対象は、計算を実行して結果または理由を返し、その実行ログを運用担当者へ提示する calc CLIである。

| 項目 | 内容 |
|---|---|
| 外部アクター | 利用者、運用担当者 |
| 外部システム | コマンドシェル |
| 入力インタフェース | コマンドライン引数、ログ提示要求 |
| 出力インタフェース | 標準出力、標準エラー出力、終了コード、計算ログ |
| 境界 | 引数受付、検証、演算、結果提示、ログ記録・提示 |
| 運用状態 | 入力待ち、検証、演算、ログ記録、正常終了、異常終了、ログ提示 |
| 前提・制約 | 1回の計算起動で1演算を実行し、有限な数値結果を扱う |

計算ログはlog/YYYY-MM-DD.logへ追記し、対象日のファイルが存在しない場合は自動生成する。正常時は実行時刻、計算内容、および計算結果を、異常時は実行時刻と異常内容を、1回の計算につき1行で記録する。logディレクトリが存在しない場合は入出力異常として標準出力へ通知する。保存期間とアクセス制御は関係者レビューで決定する。

## 2. ユースケース抽出

| ID | ユースケース | 目的 | アクター | 関連要求 |
|---|---|---|---|---|
| UC-01 | 四則演算を実行する | 結果または実行できない理由を把握する | 利用者 | CALC-STK-004 |
| UC-02 | 計算ログを確認する | 実行状況および失敗原因を調査する | 運用担当者 | CALC-STK-005 |

UC-01の実行によって計算ログが生成され、そのログをUC-02が後から利用する。アクターの目的と完了条件が異なるため、2件のユースケースに分割する。

## 4. ユースケースシナリオ分析

### UC-01 四則演算を実行する

- 事前条件：利用者がシステムを起動できる。
- トリガー：利用者が演算子と2つのオペランドを指定して起動する。
- 基本フロー：入力を検証し、演算を実行し、結果を提示してログを記録し、正常終了する。
- 代替フロー：演算子に応じて加算、減算、乗算、除算のいずれかを実行する。
- 例外フロー1：入力異常を検出した場合、計算せずに理由を提示し、失敗ログを記録して異常終了する。
- 例外フロー2：計算異常を検出した場合、結果を提示せずに理由を提示し、失敗ログを記録して異常終了する。
- 事後条件：結果または理由が提示され、その実行状況がログに記録される。

~~~plantuml
@startuml
actor 利用者
participant "コマンドシェル" as Shell
participant "calc CLI" as Calc
database "計算ログ" as Log
利用者 -> Shell: 演算子と2値を指定して起動
Shell -> Calc: コマンドライン引数
Calc -> Calc: 入力検証
alt 入力が不正
  Calc -> Log: 入力異常と理由を記録
  Calc --> Shell: 理由、非0終了コード
else 入力が妥当
  Calc -> Calc: 演算実行
  alt 有限な結果
    Calc -> Log: 正常結果を記録
    Calc --> Shell: 数値結果、終了コード0
  else 計算不成立
    Calc -> Log: 計算異常と理由を記録
    Calc --> Shell: 理由、非0終了コード
  end
end
Shell --> 利用者: 結果または理由を提示
@enduml
~~~

### UC-02 計算ログを確認する

- 事前条件：運用担当者がシステムを利用でき、UC-01によるログが記録されている。
- トリガー：運用担当者が計算ログの提示を要求する。
- 基本フロー：システムが記録済みログを取得し、運用担当者へ提示する。
- 代替フロー：正常な計算と失敗した計算を、それぞれ実行結果または失敗理由とともに提示する。
- 例外フロー：ログディレクトリが存在しない場合、またはログの読み込みに失敗した場合は、異常内容を標準出力へ提示する。
- 事後条件：運用担当者が計算の実行状況および失敗原因を確認できる。

~~~plantuml
@startuml
actor 運用担当者
participant "コマンドシェル" as Shell
participant "calc CLI" as Calc
database "計算ログ" as Log
運用担当者 -> Shell: 計算ログの提示を要求
Shell -> Calc: ログ提示要求
Calc -> Log: 記録済みログを取得
Log --> Calc: 実行時刻、計算内容と結果または異常内容
Calc --> Shell: 計算ログ
Shell --> 運用担当者: 実行状況と失敗原因を提示
@enduml
~~~

## 5. システム要求の導出

| UID | Parent | 導出元・理由 | 使用図表 |
|---|---|---|---|
| CALC-SYS-FUNC-001 | CALC-STK-004 | UC-01の基本・代替フロー：四則演算を実現するため | UC-01シーケンス図 |
| CALC-SYS-FUNC-002 | CALC-STK-004 | UC-01の基本フロー：正常結果を識別可能にするため | UC-01シーケンス図、判定表 |
| CALC-SYS-ERR-001 | CALC-STK-004 | UC-01の例外フロー1：入力不成立の理由を示すため | UC-01シーケンス図、判定表 |
| CALC-SYS-ERR-002 | CALC-STK-004 | UC-01の例外フロー2：計算不成立の理由を示すため | UC-01シーケンス図、判定表 |
| CALC-SYS-LOG-001 | CALC-STK-005 | UC-01の全フロー：後続の調査に必要な情報を残すため | UC-01シーケンス図、横断アクティビティ図 |
| CALC-SYS-LOG-002 | CALC-STK-005 | UC-02の基本フロー：記録した情報を確認可能にするため | UC-02シーケンス図、横断アクティビティ図 |
| CALC-SYS-LOG-003 | CALC-STK-005 | UC-01・UC-02の例外フロー：ログ入出力の失敗を認識可能にするため | 各シーケンス図 |

| UC-01の条件 | 演算 | 利用者への提示 | ログ |
|---|---|---|---|
| 入力が妥当で有限な結果 | 実行 | 数値結果、終了コード0 | 実行時刻、計算内容、計算結果 |
| 入力が不正 | 実行しない | 入力異常の理由、非0終了コード | 実行時刻、入力異常の内容 |
| 入力が妥当で計算不成立 | 実行するが結果不採用 | 計算異常の理由、非0終了コード | 実行時刻、計算異常の内容 |

具体的な性能値、保持期間、アクセス制御は、利害関係者との合意後に追加要求として導出する。

## 6. システム要求の分析

7要求は入出力またはログ内容を観測でき、各COMMENTのシステム試験で検証可能である。UC-01がログを生成し、UC-02が同じログを利用する依存関係がある。ログ記録失敗時の計算継続可否、保存期間、アクセス制御は未確定事項としてレビューする。

## 7. 網羅性およびトレーサビリティの確認

| 利害関係者要求 | ユースケース | シナリオ | システム要求 |
|---|---|---|---|
| CALC-STK-004 | UC-01 | 基本・代替フロー | CALC-SYS-FUNC-001, CALC-SYS-FUNC-002 |
| CALC-STK-004 | UC-01 | 例外フロー | CALC-SYS-ERR-001, CALC-SYS-ERR-002 |
| CALC-STK-005 | UC-01 | 全フローのログ記録 | CALC-SYS-LOG-001 |
| CALC-STK-005 | UC-02 | ログ提示 | CALC-SYS-LOG-002 |
| CALC-STK-005 | UC-01, UC-02 | ログ入出力失敗 | CALC-SYS-LOG-003 |

UC-01の成果物である計算ログをUC-02が利用し、両方の利害関係者要求と全システム要求に導出根拠が存在する。

## 8. レビューおよび合意

要求文、Parent、検証方法は system_requirements.sdoc と一致させる。ログの保存期間、アクセス制御、ログ記録失敗時の計算継続可否を関係者とレビューし、合意後に必要なシステム要求とソフトウェア要求を追加する。
