# calc CLI システム要求分析

## 1. システムコンテキスト

対象は、演算子と2つのオペランドを受け取り、結果または実行できない理由を返す calc CLIである。

| 項目 | 内容 |
|---|---|
| 外部アクター | 利用者 |
| 外部システム | コマンドシェル |
| 入力インタフェース | コマンドライン引数 |
| 出力インタフェース | 標準出力、標準エラー出力、終了コード |
| 境界 | 引数の受付、検証、演算、結果または理由の提示 |
| 運用状態 | 入力待ち、検証、演算、正常終了、異常終了 |
| 前提・制約 | 1回の起動で1演算を実行し、有限な数値結果を扱う |

## 2. ユースケース抽出

| ID | ユースケース | 目的 | アクター | 関連要求 |
|---|---|---|---|---|
| UC-01 | 四則演算を実行する | 指定した演算を行い、結果または実行できない理由を把握する | 利用者 | CALC-STK-004 |

包括的な利害関係者要求を起点とし、正常、入力不成立、計算不成立をUC-01のシナリオとして分析する。これらは同じ利用目的に対する結果の違いであるため、別ユースケースには分割しない。

## 4. ユースケースシナリオ分析

### UC-01 四則演算を実行する

- 事前条件：利用者がシステムを起動できる。
- トリガー：利用者が演算子と2つのオペランドを指定して起動する。
- 基本フロー：入力を受け付けて検証し、指定された演算を実行し、数値結果を提示して正常終了する。
- 代替フロー：演算子に応じて加算、減算、乗算、除算のいずれかを実行する。
- 例外フロー1：引数不足、未対応演算子または不正なオペランドを検出した場合、計算せずに理由を提示して異常終了する。
- 例外フロー2：ゼロ除算または有限な結果を得られない演算を検出した場合、結果を提示せずに理由を提示して異常終了する。
- 事後条件：正常時は結果を確認でき、異常時は実行できない理由を確認できる。

~~~plantuml
@startuml
actor 利用者
participant "コマンドシェル" as Shell
participant "calc CLI" as Calc

利用者 -> Shell: 演算子と2値を指定して起動
Shell -> Calc: コマンドライン引数
Calc -> Calc: 入力検証
alt 入力が不正
  Calc --> Shell: 入力異常の理由（標準エラー出力）
  Calc --> Shell: 非0終了コード
else 入力が妥当
  Calc -> Calc: 指定された演算を実行
  alt 有限な結果を取得
    Calc --> Shell: 数値結果（標準出力）
    Calc --> Shell: 終了コード0
  else 計算不成立
    Calc --> Shell: 計算異常の理由（標準エラー出力）
    Calc --> Shell: 非0終了コード
  end
end
Shell --> 利用者: 結果または理由を提示
@enduml
~~~

## 5. システム要求の導出

| UID | 要求文 | Parent | 導出元・理由 | 使用図表 |
|---|---|---|---|---|
| CALC-SYS-FUNC-001 | システムは、演算子と2つのオペランドをコマンドライン引数として受け取り、加算、減算、乗算、および除算を実行しなければならない。 | CALC-STK-004 | UC-01の基本・代替フロー：四則演算を実現するため | UC-01シーケンス図 |
| CALC-SYS-FUNC-002 | システムは、計算に成功した場合に数値結果を利用者へ提示し、成功を示して終了しなければならない。 | CALC-STK-004 | UC-01の基本フロー：正常結果を識別可能にするため | UC-01シーケンス図、判定表 |
| CALC-SYS-ERR-001 | システムは、コマンドライン引数が処理できない場合に計算を実行せず、理由を利用者へ通知し、失敗を示して終了しなければならない。 | CALC-STK-004 | UC-01の例外フロー1：誤計算を防ぎ入力不成立の理由を示すため | UC-01シーケンス図、判定表 |
| CALC-SYS-ERR-002 | システムは、指定された演算を有限な数値結果として完了できない場合に結果を提示せず、理由を利用者へ通知し、失敗を示して終了しなければならない。 | CALC-STK-004 | UC-01の例外フロー2：計算不成立を正常結果と区別するため | UC-01シーケンス図、判定表 |

| 条件 | 演算 | 標準出力 | 標準エラー出力 | 終了コード |
|---|---|---|---|---|
| 入力が妥当で有限な結果 | 実行 | 数値結果 | なし | 0 |
| 入力が不正 | 実行しない | なし | 入力異常の理由 | 非0 |
| 入力が妥当で計算不成立 | 実行するが結果不採用 | なし | 計算異常の理由 | 非0 |

シーケンス図と判定表で要求を明確化できるため、状態遷移図、アクティビティ図、タイミングチャートは追加しない。具体的な性能値、安全性、セキュリティ、保守性、外部環境に関する追加要求を導く根拠は現行要求にない。

## 6. システム要求の分析

4要求は入力、処理、出力、終了状態を観測でき、system_requirements.sdocの検証方法によって合否を判定できる。入力異常を演算前、計算異常を演算時として分離しており矛盾しない。標準入出力と終了コード以外の外部システムへの影響はない。全要求を必須とする。

| 利害関係者要求 | ユースケース | シナリオ | システム要求 |

| CALC-STK-004 | UC-01 | 基本フロー | CALC-SYS-FUNC-002 |

包括的な利害関係者要求から一つのユースケースを抽出し、その基本、代替、例外フローから全システム要求を導出している。全システム要求に導出元と理由がある。

## 8. レビューおよび合意

要求文とParentは system_requirements.sdoc と一致させる。検証方法は同文書を正とする。本分析では4要求を確定候補とし、正確性、完全性、妥当性を関係者レビューで確認する。新たな運用環境または品質目標が提示された場合は、利害関係者要求へフィードバックして再分析する。
