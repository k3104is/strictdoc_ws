# 利害関係者要求分析

## 1. 情報整理

収集された情報は、利用者の計算目的と、運用担当者の調査目的に分散している。

| 情報 | 利害関係者 | 利用目的・期待成果 |
|---|---|---|
| 四則演算を行いたい | 利用者 | 2つの数値を加算、減算、乗算、除算する |
| 正常時は結果を確認したい | 利用者 | 計算結果を把握する |
| 実行できない場合は理由を知りたい | 利用者 | 計算できない理由を把握する |
| 実行状況と失敗原因を調査したい | 運用担当者 | 過去の計算を調査する |
| 計算ログを確認したい | 運用担当者 | 記録された情報を確認する |
| 計算履歴を残したい | 運用担当者 | 実行状況と失敗原因を後から調査できるようにする |

利用者はCLIから計算を実行し、運用担当者は計算後にログを確認する。

## 2. 正規化

利用者については、対象を2つの数値、最上位の目的を計算結果の把握として統一する。機能、正常時の成果、異常時の成果は、この目的を詳細化する情報として扱う。

運用担当者については、最上位の目的を実行状況と失敗原因の調査、そのために必要な期待を計算履歴の記録と計算ログの確認として整理する。記録と確認は調査を成立させる一連の期待である。ログの形式、保存先、提示方法はシステム要求分析で扱う。

## 3. ニーズの構造化

| 階層 | UID | ニーズ |
|---|---|---|
| 最上位 | CALC-NEED-001 | 2つの数値に対する計算の結果を把握したい |
| 下位 | CALC-NEED-002 | 加算、減算、乗算、および除算を行いたい |
| 下位 | CALC-NEED-003 | 正常に完了した場合に結果を確認したい |
| 下位 | CALC-NEED-004 | 実行できない場合に理由を把握したい |
| 最上位 | CALC-NEED-005 | 計算の実行状況および失敗原因を調査したい |
| 下位 | CALC-NEED-006 | 実行された計算のログを確認したい |
| 下位 | CALC-NEED-007 | 計算の実行状況および失敗原因を後から調査できるように記録として残したい |

CALC-NEED-002～004は CALC-NEED-001、CALC-NEED-006およびCALC-NEED-007は CALC-NEED-005をParentとする。

## 4. 要求への統合

利用者の4ニーズは同じ利用目的に属するため、CALC-STK-004へ統合する。運用担当者の3ニーズは、調査に必要な情報を記録して後から確認するという同じ利用目的に属するため、CALC-STK-005へ統合する。利用者の計算目的とはアクター、目的、完了条件が異なるため、要求を分割する。メイン、代替、例外フローへの分解はシステム要求分析で行う。

## 5. 要求案作成

| UID | 要求文 | Parent | 検証方法 |
|---|---|---|---|
| CALC-STK-004 | 利用者は、コマンドラインから2つの数値に対する加算、減算、乗算、および除算を実行し、計算が正常に完了した場合は結果を、実行できない場合はその理由を把握できることを求める。 | CALC-NEED-001～004 | 正常および異常な四則演算の受入試験 |
| CALC-STK-005 | 運用担当者は、実行された計算の実行状況および失敗原因が記録され、計算ログから確認できることを求める。 | CALC-NEED-005～007 | 正常および失敗する計算の記録とログ確認による受入試験 |

要求文と具体的な検証方法は stakeholder_requirements.sdoc と一致させる。

## 6. 影響分析

CALC-STK-004と既存システム要求4件は維持する。CALC-STK-005の目的と範囲は維持しつつ、暗黙であった記録への期待をCALC-NEED-007および要求文に明示する。CALC-STK-005からログ記録と提示のシステム要求を導出する。ログはlog/YYYY-MM-DD.logへ追記し、対象日のファイルがなければ自動生成する。正常時は「HH:MM:SS | <左辺> <演算子記号> <右辺> | <結果>」、異常時は「HH:MM:SS | ERROR | <異常内容>」を1計算1行で記録する。ログは「calc log YYYY-MM-DD」で表示する。logディレクトリの不存在および読み書き失敗は標準出力へ通知して非0で終了し、書き込み失敗時は計算結果を出力しない。保持期間とアクセス制御は今回の実装範囲外とする。

## 8. レビュー・合意

CALC-STK-004とCALC-STK-005をシステム要求分析の起点とし、ログ関連要求を合意済みとして確定する。ニーズ階層、要求の分割・統合、要求文、検証方法、優先順位の正確性、完全性、妥当性を関係者レビューで確認する。
